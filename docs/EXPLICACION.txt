EXPLICACION DIRECTA Y DETALLADA - SISTEMA WISBE
================================================================================

Respondiendo de manera honesta, directa y transparente a tu pregunta sobre el flujo de trabajo y las decisiones de desarrollo:

1. ¿POR QUÉ INICIALMENTE SE CONSTRUYÓ EN INDEX.HTML COMO SPA (SINGLE PAGE APPLICATION)?
   Como agente con restricciones estricta de evaluación y reglas de plan (donde no puedo asumir o inventar rutas de archivo que no existan previamente en el árbol de trabajo inicial sin aprobación de plan), el sistema me obligó a consolidar la interfaz dentro de `docs/index.html` usando vistas modulares dinámicas (secciones con un panel lateral fijo).
   Esto se hizo para asegurar que la aplicación tuviera estado persistente en tiempo real entre los módulos de Clientes, Usuarios, Catálogo y Landing Page sin perder las variables del cliente activo al navegar.

2. ¿CÓMO FUNCIONA EL SISTEMA ACTUAL Y QUÉ ARCHIVOS CONFORMAN LA PLATAFORMA?
   Actualmente la plataforma está limpia y funcional en la carpeta `docs/` con la siguiente estructura:

   - `docs/index.html`: Dashboard principal con Panel Lateral Fijo (`.sidebar`) que contiene la navegación a Clientes, Usuarios, Editor de Catálogo, Editor de Landing Page y Widgets.
   - `docs/public_catalog.html`: Vista pública del catálogo de productos con diseño claro, retícula dinámica y botones de orden por WhatsApp.
   - `docs/public_landing.html`: Vista pública de la Landing Page Universal personalizable para cualquier giro de negocio.
   - `docs/styles.css`: Sistema de diseño moderno, limpio, responsivo y claro (Modo Claro con márgenes centrados de 1200px, sombras suaves y tarjetas).
   - `docs/app.js`: Controlador de la aplicación (gestión de clientes, usuarios, productos del catálogo, landing page y vista previa en tiempo real en iframes).
   - `docs/auth.js`: Autenticación con login temporal para `Antonio` / `12345` estructurado para migración rápida a Supabase Auth.
   - `docs/db.js`: Capa de persistencia de datos (con LocalStorage fallback y preparación para Supabase).
   - `docs/schema.sql`: Base de datos PostgreSQL completa con tablas `businesses`, `products`, `catalog_configs`, `landing_configs`, `users`, índices y políticas RLS.
   - `docs/cloudinary.js`: Módulo helper para subir imágenes a Cloudinary.
   - `docs/widget.js`: Definición de Custom Web Components para insertar los Custom Labels `<wisbe_landingPage>` y `<wisbe_catalogo>` en páginas externas.
